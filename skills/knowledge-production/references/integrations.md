# 文案清理与剪映自动剪辑的接入

这两项是对应阶段的默认执行环节，不是交付后再让用户自行调用的建议。普通文字阶段只读取文案部分，进入视频阶段再读取剪映部分。

## 随包定位

本包完整携带 [文案白名单](../vendor/text-cleanup/RULES.md) 和 [剪映源码运行时](../vendor/jianying-editor/README.md)。不再依赖原作者设备中已安装的两个 skill。所有路径相对于此文件或包根目录；完整文案规则是对应执行依据。

制作时优先运行包内 `scripts/doctor.py` 检查当前阶段所需依赖。有文件读取但没有命令执行能力时，可完成文稿并准备制作输入；缺少剪映能力时明确等待，不声称自动剪辑完成。没有文件读取能力的 agent 使用发布包中的完整 prompt 入口。

## 文案去 AI 味：`lieflat-less-ai-tone`

### 输入与顺序

输入是结构和事实已经稳定、尚未录音定时的正文。存在语言风格指南、语言 DNA、用户参考文稿时先读；作者真实风格优先于通用“像 AI”的判断。

1. 保存原文为清理前版本，锁定标题层级、章节和段落顺序、段落数量、列表、表格、引用与代码块位置。
2. 读取完整 `vendor/text-cleanup/RULES.md`，逐项检查其白名单。当前规则涉及翻案腔、顿号罗列、相邻句骨架、破折号/冒号、小标题编号、拟人化喻体、已有具体信息、起手式、限定的翻译腔及段首回指；这个索引不能替代完整触发条件和例外。
3. 每一处修改都能对应明确规则，只改解决命中问题的必要部分；拿不准就保留。没有命中的句子逐字保留。
4. 比较前后版本，按配套 skill 的最终验收清单复核，撤销任何超出白名单或改变信息的改动。规则例子若与其信息守恒、框架保留的硬边界冲突，服从硬边界，不照抄会丢失事实的示例。
5. 保存清理后的实际全文并将它设为后续排版、提词或配音所用稿件。简报记录执行状态与版本；用户没有要求时无需贴出冗长逐句改动报告。

### 不可跨越的边界

不增加或删减事实、观点、数字、日期、引语、来源、因果、动机、限定词或案例。不能把“可能”“通常”去掉，不为“更具体”补故事，不为“更像人”加第一人称、拆段落或重排结构。问句、必要的编号、作者有意使用的表达等按原 skill 例外保留。

对原文的事实纠错或结构修复回到研究/写作阶段单独处理，不能混入去 AI 味。涉及用户核心意思时按主流程询问；修好后再对新增文字做一次有界清理。

以下内容不改：他人原文引用、代码、外语段落、用户要求逐字保留的文字，以及已录音的实际说话内容。已有录音时可以清理新写的标题或介绍，但不能润色字幕后假装与声音一致。

若用户只要查证、素材或结构建议，尚无要制作的成稿，则这一环节标“不适用”。没有命中时标“已检查，无需改写”，不要编造修改。AI 检测分数不证明作者身份，不引发无止境改稿。

## 自动剪辑：`jianying-editor`

### 开工输入

确认输入实际具备：

- 作品简报：主要观点、形式/画幅、交付类型、用户确认与禁止项。
- 清理后的制作稿；如有用户录音，以确认过的最终录音为时间事实。
- 可打开的本地素材及其来源、可用区间、用途与限制。
- 镜头表：旁白/原声的成片区间、源文件与源入出点、构图、字幕及声音动作。
- 字幕数据或可用的转写/对齐能力，BGM 来源及风格选择；不需要配乐时不硬加。

输入有缺口先处理。用户观点和形式已确认，可自主找素材与做常规剪辑；缺少用户录音则先交付清理后的录音稿并等待，不能擅自改用示例 TTS 声音。已授权合成配音时才使用其配音接口。

### 实际执行链

1. 读取 [可迁移剪辑接口](jianying-runtime.md)。将确认稿、录音、镜头和字幕整理为 `edit-plan.json`，素材使用相对该文件目录的路径。以包内 `assets/edit-plan.example.json` 为结构参考，不把示例字幕或虚构素材当成已就绪输入。
2. 运行 `python <包根目录>/scripts/doctor.py --mode jianying --drafts-root "<目标草稿目录>"`。探测结果只是依赖线索，不能证明软件兼容或主观检查通过。剪映不在执行设备上时，只能先生成待迁移工程；如果这改变了用户的交付要求则先询问。
3. 在作品目录保存计划与素材；按已选画幅和镜头源区间安排时间线，旁白、原声、BGM 与字幕分别编辑。真实录音和配音需先完成，不能以清理后的文字替换已说出的台词。
4. 先运行 `python <包根目录>/scripts/build_jianying.py edit-plan.json --drafts-root "<目标草稿目录>" --validate-only`，再去掉 `--validate-only` 实际构建。脚本拒绝同名覆盖，复制素材到新工程，调用内置 `JyProject` 保存；未完成目录有 `BUILD_INCOMPLETE.txt` 标记，不可交为成品。
5. 检查 `build-report.json`、实际草稿 JSON、独立轨道、素材路径、镜头顺序与声音字幕对应。在有剪映的设备实际打开工程并抽查画面/声音；未实际打开时保持 `application_open_verified: false`。
6. 仅需草稿时交付工程。要求导出时，再使用宿主能用的应用操作或当前剪映支持的导出方式；随包生成器不假设每个版本都能自动导出。检查实际输出文件后才称已导出。

同一错误依据实际报错修复一次；仍失败就停止盲试，给出下一种可验证的兼容路线。镜头导入失败不能悄悄删除，字幕或片段重叠不能靠挪动关键时间锚点掩盖。高级特效、云端音乐、TTS 和录屏不属于基础生成器保证的能力，可按用户所选方案使用宿主工具扩展。

### 音乐、兼容性和完成边界

配乐方向已确认或用户授权按既定风格选曲时自主选择并试听；没有方向且会明显改变作品气质时，先给具体候选。示例中的画幅、时长与音量不是作品默认值，按当前简报和实际听感调节。

草稿加密、版本不兼容或文件被应用占用时，保留原工程，改用经过验证的克隆/兼容路径或可用的应用操作。若必须用户操作才能继续，给出具体所需操作和已完成部分；不承诺所有剪映版本都能自动导出。

草稿至少验证：目录和素材存在、保存成功、有真实视频片段、声音在正确音轨、需要字幕时存在对应字幕、片段顺序和时长合理。再检查关键画面、剪口、配乐、字幕与应用可打开性；任何没做过的检查都不能填“通过”。

交付实际剪映工程及其名称/位置、必要源素材、清理后的文稿、最终旁白、字幕、镜头与来源记录、执行脚本及检查结果。按需求取舍，别用一个扁平合成 MP4 冒充口播、原声、配乐、字幕都可独立编辑的工程。
